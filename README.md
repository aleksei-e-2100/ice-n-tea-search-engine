# iCE && tEA Search Engine

## Аннотация
iCE && tEA Search Engine представляет собой поисковый движок, предназначенный для корпоративного портала. Он предназначен для быстрого поиска информации по большому количеству текстовых документов и может использоваться как самостоятельное приложение либо как компонент веб-сайта, веб-сервиса или любой другой программной системы. Взаимодействовать с ним может любой внешний интерфейс или приложение, передавая поисковые запросы через JSON-файл и получая результаты поиска в выходном JSON-файле.

### Движок работает по следующим принципам:
1. Перед запуском в файле `config.json` задается список файлов, по которым будет выполняться поиск.
2. Движок обходит указанные файлы и строит индекс, позволяющий находить наиболее релевантные документы для любого поискового запроса. Во время индексации выполняется автоматическая токенизация слов: знаки препинания в начале и конце слова удаляются.
3. Поисковые запросы передаются через JSON-файл `requests.json`. Запрос представляет собой набор слов, используемых для поиска в документах.
4. Запрос токенизируется тем же способом, что и текстовые документы. После этого движок находит документы, содержащие указанные слова.
5. Результаты поиска ранжируются, сортируются и сохраняются в JSON-файл `answers.json`. Любое приложение может прочитать этот файл и использовать результаты поиска.


## Использование поискового движка

Файлы `config.json` и `requests.json` должны находиться в одной директории с исполняемым файлом. Без них запуск невозможен. Содержимое файлов проверяется при запуске.

### В `config.json`:
- Файл должен содержать обязательные ключи "config" с настройками поиска и "files" со списком файлов для поиска.
- В файле должна быть указана версия конфигурации ("version"). При отсутствии версии или ее несоответствии версии движка запуск невозможен.
- Необязательный параметр "max_responses" (максимальное количество ответов на один запрос). Если "max_responses" не указан, по умолчанию возвращаются пять наиболее релевантных документов.
- Список файлов должен быть задан в виде текстовых строк. Если файл отсутствует или его невозможно открыть, будет выведено сообщение об ошибке.

### В `requests.json`:
- Файл должен содержать поисковые запросы, которые будут обработаны движком.


## Примеры конфигурации и результатов поиска
Образцы файлов `config.json` и `requests.json` находятся в директории `release`.  
Образцы текстовых файлов для поиска в них находятся в директории `release/text_files`.

### `answers.json`:
Образец файла `answers.json` также находится в директории `release`.
- Ключ "request00X" соответствует индексу запроса (в соответствии с порядком запросов в `requests.json`).
- Ключ "result" имеет значение true, если найден хотя бы один документ, иначе false. Для пустых запросов также возвращается false.
- Ключ "doc_id" содержит индекс документа, в котором найден результат (в соответствии с порядком файлов в (в соответствии с порядком файлов в `config.json`, начиная с нуля).
- Ключ "rank" содержит уровень релевантности документа. Если запросу соответствует несколько документов, они перечисляются в порядке убывания релевантности.


## Ограничения
Поисковый движок имеет следующие ограничения, которые обусловлены целями создания данного проекта:
- Поддерживаются работа только с обычными текстовыми файлами (например, .txt). Поиск внутри документов Word и других бинарных форматов не выполняется.
- Поисковый движок чувствителен к регистру символов. Слова должны совпадать с регистром, указанным в запросе.
- Во время токенизации знаки препинания удаляются только в начале и конце слова. Знаки препинания внутри слова считаются частью слова.
- Различные грамматические формы слова (падежи, склонения, времена и т.д.) считаются разными словами. Например, слова "дом" и "дома" будут рассматриваться как разные токены и не будут сопоставляться друг с другом. Лемматизация, стемминг и морфологический анализ не выполняются.


## Технологический стек
- Поисковый движок использует C++23 и контейнеры STL.
- Индексация файлов выполняется в несколько потоков. Чтение файлов всегда выполняется последовательно (в одном потоке), чтобы избежать проблем при работе со старыми HDD. Реализован тред-пул. После чтения файла с диска поисковый движок передает его в тред-пул для индексации. Для минимизации потребления памяти и обеспечения возможности поиска по большому количеству файлов содержимое файла не хранится в памяти после завершения индексации.

Внешние библиотеки:
- JSON for Modern C++ для работы с JSON.
- GoogleTest для модульного тестирования.


## Сборка
Проект использует CMake.
Поддерживаемые компиляторы:
Windows: MSVC, MinGW
Linux: gcc (g++), clang
При первом запуске CMake требуется доступ в интернет. Это необходимо для загрузки библиотек JSON for Modern C++ и GoogleTest.

### Пример процедуры сборки:
Клонируйте репозиторий.  
Перейдите в директорию проекта.  

Выполните следующие команды:  

```
mkdir build
cd build
cmake -DCMAKE_BUILD_TYPE=Release ..
cmake --build .
```

Готовый исполняемый файл будет расположен в директории `release`.
